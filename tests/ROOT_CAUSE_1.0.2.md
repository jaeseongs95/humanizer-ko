# 1.0.2 원인 분석과 검증 기록

검증일: 2026-09-08. 문체 규칙과 원문 주장 보존의 충돌, 불충분한 의미 비교, 문체 샘플 우선순위 및 평가 기준의 변동을 조사했다.

## 조사 범위와 확정할 수 있는 원인

설치 누락이나 구버전 실행이 원인은 아니었다. 조사 시작 때 작업 폴더와 설치본의 1.0.1 SKILL.md 해시가 일치했고, 이후 실험은 별도로 저장한 지침 스냅샷을 직접 읽도록 했다.

제품 수준에서 확인한 설계 결함은 다음과 같다.

1. **편집 대상의 정의가 보존 계약과 충돌했다.** 1.0.1은 본질·핵심 표현을 걷어내거나 측정 가능한 변화만 쓰도록 하면서, 다른 곳에서는 원문의 태도·주장 강도를 보존하라고 했다. 글쓴이의 정의·중요도·개인적 평가가 문체 장식인지 실제 주장인지의 경계가 충분히 명확하지 않았다.
2. **숫자·명사의 보존을 의미 보존과 혼동하기 쉬운 절차였다.** 이름·날짜가 남아도 결정 행위가 일정 상태로 바뀌거나, 행동한 날이 그 행동으로 정한 날짜로 바뀔 수 있다. 무엇을 누구에게 어떻게 귀속시키는지까지 대조하는 절차가 필요했다.
3. **문체 적용 범위와 문자 보호 경계가 불충분했다.** 샘플이 있는 글의 어미를 원문대로 두거나, 여러 글의 어미를 서로 섞는 결과가 관측됐다. URL 자체의 부분 문자열은 남아도 공백을 없애면 뒤의 조사가 URL에 붙을 수 있었다.
4. **검증 기준이 출력 이후 바뀌었다.** 이전에는 ‘본질→용도’를 통과시켰다가 이후 감사에서 실패로 봤다. 이를 고정하지 않은 단회 성공과 패키지 테스트 통과로 수정 효과를 충분히 확인했다고 판단한 것은 잘못이었다.

이는 지침·검증 체계에서 확인한 결함이다. 모델 내부의 어느 계산이 개별 오답을 만들었는지까지 증명한 것은 아니다. 아래 비교는 원인 가설을 좁히는 소규모 관측이며 통계적 인과 추정이나 실패율 측정이 아니다.

## 사전에 고정한 비교 실험

[EVALUATION_PROTOCOL.md](EVALUATION_PROTOCOL.md)의 C01–C06 조건을 출력 전에 확정했다. 같은 스냅샷에서 K(1.0.1 그대로), M(패턴 2·3·13의 편집/보존 경계만 변경), R(작업 순서만 의미 대조·부분 복원 절차로 변경)을 만들었다.

조건마다 `gpt-5.6-terra / high`의 새 에이전트 두 개를 사용했다. 지침 파일의 경로 외에는 같은 요청·모델·추론 설정을 사용했고, 기존 대화·정답·평가 기준은 실행자에게 제공하지 않았다. 서버 내부 상태·시드·실행 시각은 통제하지 못했다.

별도의 `gpt-5.6-sol / high` 감사자는 모델·조건 매핑 없이 익명 T1–T6 출력과 원문·고정 규약만 받았다. 매핑은 T1=K1, T2=M1, T3=R1, T4=K2, T5=M2, T6=R2다.

| 조건 | C01–C06 두 실행의 독립 판정 | 관측 |
| --- | --- | --- |
| K: 기존 지침 | 7/12 통과 | 본질 주장의 약화, 실제 대비·비교의 소실 |
| M: 표현별 경계만 수정 | 10/12 통과 | 본질 주장은 보존했지만 샘플 미반영과 결정 행위 생략이 각각 발생 |
| R: 절차만 수정 | 10/12 통과 | 한 실행에서 본질 주장이 다시 용도로 바뀜. 다른 실행은 샘플 어미 미반영 |

감사 전체 판정은 27/36 통과, 의미 실패 7건, 샘플 미반영 2건이었다. ‘중대한→중요한’ 같은 정도 표현 차이만으로는 추가 실패를 만들지 않았다. 본질/핵심과 단순 중요성의 차이는 사전에 정한 엄격한 의미 조건에 따라 판정했다.

표현별 경계 수정만으로 모든 보존 문제가 해결되지 않았고, 의미 비교 절차만 추가해도 충돌하는 패턴 규칙의 영향을 완전히 없애지 못했다. 따라서 두 변경을 함께 적용했다. 복합 수정의 기여를 각 문장 단위로 통계적으로 분리했다고 주장하지 않는다.

원문 스냅샷, 두 조건의 정확한 치환 내용, 입력, 36개 실제 출력과 실행 설정은 [cause.json](evidence/1.0.2/cause.json)에 있다.

## 후보별 검증과 추가 수정

### 후보 1

표현별 경계와 의미 대조·부분 복원을 결합하고 샘플 어미 우선순위를 명시했다. 원인 비교 입력 6개와 새 주제 H01–H08을 두 새 에이전트로 실행했다.

실제 파일 편집에서 ‘운영팀은 9월 8일 점검일을 확정했습니다’가 ‘운영팀은 점검일을 9월 8일로 확정했습니다’로 바뀌었다. 날짜 값만 남았을 뿐 날짜의 역할이 달라졌으므로 배포하지 않았다. 원자료는 [candidate-1.json](evidence/1.0.2/candidate-1.json)에 보존했다.

### 후보 2

숫자·날짜와 사건·대상의 연결, 행위일과 대상일의 구별을 대조 절차에 추가했다. H09·H10을 새 회귀/전이 입력으로 고정하고 전체 입력을 다시 실행했다.

파일의 날짜 역할 변화는 재현되지 않았다. 그러나 두 번째 문장 실행에서 H10의 합니다체가 해라체로 바뀌었고, H04의 URL 뒤 공백이 없어져 조사가 링크에 붙었다. 이를 통과로 묵인하지 않고 글별 문체 범위와 URL 경계 보존을 추가로 보강했다. 원자료는 [candidate-2.json](evidence/1.0.2/candidate-2.json)에 있다.

## 범위와 한계

이 감사는 제작 이력을 공유하지 않은 AI 서브에이전트를 이용한 것이며 외부 기관이나 인간 제3자의 인증은 아니다. 최종 실행자는 정답이나 의심 결함을 받지 않았고, 평가자는 고정 규약에 따라 실제 결과를 비교한다. 이번 테스트의 통과를 모든 입력·모델에서의 무오류 보장으로 확대하지 않는다. 구버전 관측과 실패한 후보도 삭제하지 않아 재작업 과정을 확인할 수 있게 했다.
