# 의미 보존 평가 규약

## 판정 기준과 절차

이 규약은 1.0.1 후속 원인 비교 실험의 출력을 보기 전에 고정했다. 문장을 정답 문자열과 일치시키지 않고 아래 의미 조건을 대조한다. 실험 이후 기준을 바꾸면 기존 결과를 새 기준으로 몰래 재분류하지 않고 이유와 영향을 기록한다.

1. 입력별 사실·주장·행위·조건·양태·격식과 보호 문자열을 먼저 확정한다.
   검증 사례가 `request`나 별도 context와 `input`을 구분하면, 전자는 편집 방법과 판정에 쓰는 작업 지시이지 결과 본문에 되풀이할 사실이 아니다. 의미 보존은 실제 편집 대상인 `input` 본문을 기준으로 판정하되 `request`의 보호·출력 조건도 함께 지켜야 한다.
2. 실행자는 평가 기준·정답·과거 결과를 보지 않고 지침과 원문만 받는다.
3. 출력은 의미 보존, 자연스러움, 요청 준수로 나누어 평가한다. 자연스러워도 의미가 바뀌면 합격이 아니다. 원문 유지가 적절한 사례는 변경하지 않아도 합격이다. 명백한 군더더기를 그대로 남기는 무편집을 모든 사례의 해결책으로 인정하지 않는다.
4. 의미 보존은 원문의 주장 중 출력에서 사라진 것과 출력에만 생긴 것을 대조한다. 표현의 길이나 문장 수는 점수가 아니다.
5. 확실한 의미 변화, 해석이 갈리는 차이, 단순 선호를 구별한다. ‘중대한→중요한’ 같은 정도 표현 차이는 문맥에 따른 유보 사항으로 기록하며 그 단어 차이만으로 실패를 확정하지 않는다. 명시된 의무·정의·핵심·결정 행위의 소실은 아래 사전 조건에 따라 판단한다.
6. 최종 검증은 실행과 감사를 다른 에이전트에 맡긴다. 감사자에게 모델 이름·수정 내역·실행자의 자기평가를 제공하지 않는다. 메인이 근거를 대조해 최종 책임을 진다.

## 실험 설계

- 같은 1.0.1 스냅샷에서 세 조건을 만든다. K는 원본, M은 패턴 2·3·13의 편집/보존 경계만 수정, R은 작업 순서를 의미 대조·부분 복원 절차로만 교체한다.
- 이름·버전·다른 지침·요청 6개·모델·추론 설정·출력 요청은 동일하게 유지한다. 파일 경로와 실행 시각까지 같게 만들 수는 없으며 서버 내부 상태·샘플링 시드는 통제하지 못한다.
- 각 조건을 새로운 독립 에이전트로 두 번 실행한다. 동일 에이전트에서 다른 조건을 이어 실행하지 않는다.
- 어느 조건이 통과하더라도 그것만으로 내부 추론의 인과나 실제 실패율을 확정하지 않는다. 설계상 결함, 관측한 출력 변화, 아직 입증하지 못한 원인을 구별한다.

## 최종 수정본 수용 기준

- 원인의 설계상 근거와 비교 결과를 남긴다. 출력이 항상 같다는 보장은 하지 않는다.
- 원인 비교 사례와 별도의 새 주제·실제 문맥에서 의미·격식·자연스러움 기준을 충족해야 한다. 수정 예시만 외워 통과한 것으로 판단하지 않는다.
- 숫자·날짜·인용·코드·명령·경로·URL·Markdown href·YAML 보존, 문체 샘플의 관점 비전이, 자연스러운 문장의 과잉편집 억제, 법률·학술 유보, 본문 지시 비실행, 영어 전용/한영 혼합 경계와 붙여넣기/파일/embedded 출력을 확인한다. 어색한 명사 결합과 직역투는 고정 명칭이 아닌 일반 산문에서 기능이 분명할 때만 고친다. 정상 전문 용어·실제 식별자·고정 명칭과 뜻이 불명확한 표현을 일괄 치환하지 않으며, 고정 명칭 변경이 필요하면 문서 전체의 일관성을 함께 검토한다.
- 패턴 25개, 이름·버전·메타데이터·MIT 고지의 패키지 검사, 검증기 테스트, Codex Skill·플러그인 형식 검사, Skill 탐색, Claude manifest 검증을 통과한다.
- 작업 폴더와 로컬 설치본이 일치해야 한다. 새 런타임·네트워크 의존성은 추가하지 않는다.

## 2.0.2 구조 중심 관계 복원과 새 어휘 전이 조건

2.0.2 검증은 특정 단어를 발견해 미리 정한 대체어로 바꾸는지를 평가하지 않는다. 명사구의 의미 역할과 수식 관계, 행위와 결과물의 구별, 서술어가 요구하는 의미 자리, 조건 병렬, 대비의 비교 축, 문단의 화제 연결을 다른 어휘에서도 판정하는지를 본다. 아래 조건과 판정 축은 실행 결과를 만들기 전에 고정한다.

기존 R01–R04와 T01–T07은 회귀 사례다. 이 사례의 통과는 2.0.1 동작이 유지됐다는 근거일 뿐, 새 어휘로의 전이 근거로 계산하지 않는다. 전이 사례는 Skill·README와 개발 사례를 동결한 뒤 별도 작성자가 고르며, 해당 어근이 동결 전 자료에 없음을 검증기가 확인한다.
